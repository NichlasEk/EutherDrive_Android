# Sega 32X Performance Flags

Status: 2026-05-02

This is a quick reference for current 32X performance-related environment flags in
EutherDrive. Values here are intended for local ROM testing, not final accuracy.

## Recommended First Pass

### `EUTHERDRIVE_S32X_SYNC_QUANTUM`

Default: `1`

Coarse global 32X scheduler knob. It scales multiple slice sizes together so the
M68K and SH2 scheduling quanta grow in sync.

Currently affects defaults for:

- `EUTHERDRIVE_S32X_M68K_INTERLEAVE_SLICE`: `224 * quantum`
- `EUTHERDRIVE_S32X_COARSE_FRAME_SCHEDULER_LINES`: `8 * quantum`
- `EUTHERDRIVE_S32X_DEFERRED_LINE_BATCH_LINES`: `2 * quantum`
- `EUTHERDRIVE_S32X_SCAFFOLD_SH2_SLICE`: `96 * quantum`
- `EUTHERDRIVE_S32X_M68K_COMM_SYNC_SLICE`: `128 * quantum`

If any of those specific flags are set, they override the scaled default.

Suggested tests:

```bash
EUTHERDRIVE_S32X_SYNC_QUANTUM=2
EUTHERDRIVE_S32X_SYNC_QUANTUM=4
```

Observed quick Doom result:

- `1`: about `13.46 ms/frame`
- `2`: about `13.01 ms/frame`
- `4`: about `12.15 ms/frame`

Knuckles boot sanity with `2`: OK in headless 180-frame test.

## Scheduler / Batching

### `EUTHERDRIVE_S32X_COARSE_FRAME_SCHEDULER`

Default: `false`, unless `EUTHERDRIVE_S32X_SYNC_QUANTUM > 1`

Runs the MD/32X frame scheduler in larger line groups. It avoids some per-line
scheduling overhead while keeping a consistent quantum. It automatically falls
back to line-sized slices during boot-safe frames and when 32X H-interrupts are
enabled.

### `EUTHERDRIVE_S32X_COARSE_FRAME_SCHEDULER_LINES`

Default: `8`, scaled by `EUTHERDRIVE_S32X_SYNC_QUANTUM`

Controls how many VDP lines are grouped into one coarse scheduler quantum.

### `EUTHERDRIVE_S32X_M68K_INTERLEAVE_SLICE`

Default: `224`, scaled by `EUTHERDRIVE_S32X_SYNC_QUANTUM`

Controls M68K slice size when interleaving with the 32X core.

### `EUTHERDRIVE_S32X_SCAFFOLD_SH2_SLICE`

Default: `96`, scaled by `EUTHERDRIVE_S32X_SYNC_QUANTUM`

Controls SH2 scheduler slice size inside the 32X scaffold.

### `EUTHERDRIVE_S32X_M68K_COMM_SYNC_SLICE`

Default: `128`, scaled by `EUTHERDRIVE_S32X_SYNC_QUANTUM`

Controls how far SH2s catch up around M68K communication-port sync.

### `EUTHERDRIVE_S32X_ACCESS_DRIVEN_LINE_BATCH`

Default: `true`

Lets M68K 32X peripheral accesses trigger targeted SH2 catch-up instead of
always paying finer global interleave cost.

### `EUTHERDRIVE_S32X_LINE_BATCH_BOOT_SAFE_FRAMES`

Default: `8`

Keeps aggressive batching disabled during the earliest boot frames.

### `EUTHERDRIVE_S32X_LINE_BATCH_IO_COOLDOWN_CYCLES`

Default: `2048`

Cooldown after 32X I/O-sensitive accesses before batching becomes aggressive
again.

### `EUTHERDRIVE_S32X_DEFERRED_LINE_BATCH`

Default: `false`

Defers multiple 32X line catch-ups into a larger batch. Potential speed win, but
more timing risk than the normal access-driven line batching.

### `EUTHERDRIVE_S32X_DEFERRED_LINE_BATCH_LINES`

Default: `2`, scaled by `EUTHERDRIVE_S32X_SYNC_QUANTUM`

Number of line batches to defer before flushing.

## SH2 Execution Core Experiments

### `EUTHERDRIVE_S32X_FAST_CORE`

Default: `false`

Uses the fast decoded opcode path when available. Mixed results so far.

### `EUTHERDRIVE_32X_BLOCK_INTERP`

Default: `false`

Enables the SH2 decoded-block interpreter. Conservative block mode.

### `EUTHERDRIVE_32X_BLOCK_INTERP_AGGRESSIVE`

Default: `false`

Allows more opcodes in decoded blocks. More risk than conservative block mode.

### `EUTHERDRIVE_S32X_TURBO_STRAIGHT_LINE`

Default: `false`

Experimental straight-line SH2 turbo path. It avoids some dispatch overhead, but
was not clearly positive in earlier tests.

### `EUTHERDRIVE_S32X_MEM_LOOP_FUSION`

Default: `false`

Experimental fusion for selected memory polling/copy loops. Worth retesting with
new scheduler settings.

### `EUTHERDRIVE_S32X_DISABLE_BLOCK_JIT`

Default: `false`

Disables the internal block-JIT/fast-block path. Mainly useful for A/B testing.

### `EUTHERDRIVE_S32X_DISABLE_TIGHT_DELAY_BATCH`

Default: `false`

Disables tight delay-loop batching. Useful to confirm whether a game depends on
small busy-wait timing details.

### `EUTHERDRIVE_S32X_DISABLE_POLL_LOOP_ACCEL`

Default: `false`

Disables SH2 polling-loop acceleration. Useful for regression diagnosis.

## Wait / Poll Fast-Forward

### `EUTHERDRIVE_S32X_SMART_WAIT_SKIP`

Default: `true`

Skips selected wait states in the scaffold. Already enabled.

### `EUTHERDRIVE_S32X_SMART_WAIT_BOOT_FRAMES`

Default: `8`

Boot-safe frame count before smart wait skipping becomes active.

### `EUTHERDRIVE_S32X_WAIT_FAST_FORWARD`

Default: `false`

Fast-forwards SH2 wait loops from the scaffold scheduler.

### `EUTHERDRIVE_S32X_SCHED_WAIT_FF`

Default: `false`

SH2 scheduler wait-loop fast-forward.

### `EUTHERDRIVE_S32X_SCHED_POLL_WAIT_FF`

Default: `false`

SH2 scheduler polling-loop fast-forward.

## Bigger Timing / Bus Cheats

### `EUTHERDRIVE_S32X_SH2_BUDGET_SCALE`

Default: `1.0`

Scales SH2 cycle budget. Lower values can increase host fps by effectively
underclocking SH2 work, but may change game behavior. Previous hack value was
around `0.69`.

### `EUTHERDRIVE_S32X_SCAFFOLD_SH2_BUDGET`

Default: nominal `400000`

Overrides SH2 frame budget directly.

### `EUTHERDRIVE_S32X_WIDE_FB_BUS`

Default: `false`

Reduces framebuffer bus latency. It can help some write-heavy cases, but earlier
profiling showed SH2 instruction overhead was the larger bottleneck.

### `EUTHERDRIVE_S32X_M68K_ACCESS_SYNC_CYCLES`

Default: `4`

Cost used when M68K 32X peripheral accesses force SH2 sync.

### `EUTHERDRIVE_S32X_COMM_SYNC_CHUNK`

Default: parsed in SH2 bus

Controls chunking for communication sync in the SH2 bus.

### `EUTHERDRIVE_S32X_AGGRESSIVE_COMM_READ_SYNC`

Default: parsed in SH2 bus

More aggressive communication-port read synchronization.

### `EUTHERDRIVE_S32X_COMM_FIFO_WINDOW`

Default: `512`

Controls how long recent communication writes stay visible in the scaffold
write FIFO window.

### `EUTHERDRIVE_S32X_PRECISE_SH2_DATA_CACHE`

Default: `false`

More precise SH2 data cache behavior. Usually a performance cost, useful for
accuracy diagnosis rather than speed.

## Suggested Test Matrix

Start with these, in this order:

```bash
EUTHERDRIVE_S32X_SYNC_QUANTUM=2

EUTHERDRIVE_S32X_SYNC_QUANTUM=4

EUTHERDRIVE_S32X_SYNC_QUANTUM=4 EUTHERDRIVE_S32X_FAST_CORE=1

EUTHERDRIVE_S32X_SYNC_QUANTUM=4 EUTHERDRIVE_32X_BLOCK_INTERP=1 EUTHERDRIVE_32X_BLOCK_INTERP_AGGRESSIVE=1

EUTHERDRIVE_S32X_SYNC_QUANTUM=4 EUTHERDRIVE_S32X_MEM_LOOP_FUSION=1

EUTHERDRIVE_S32X_SYNC_QUANTUM=4 EUTHERDRIVE_S32X_WAIT_FAST_FORWARD=1
```

Good benchmark ROMs:

- Doom 32X: CPU-heavy and a good speed gauge.
- Knuckles' Chaotix: timing-sensitive boot/gameplay sanity.
- After Burner Complete: useful for M68K/VDP/32X balance.
