# Resident Evil 2: graphics completion and PAL startup timing

Linux desktop continuation from the existing uncommitted N64 work. The European
Resident Evil 2 ROM now reaches language selection and the title menu with the
live GPU core. This fixes two independent startup stalls; it is not a claim of
complete game compatibility.

Artifacts: `.build-tmp/n64-re2-2026-09-23/`. ROM SHA-256:
`52093e994c89848b17c8e6f26546d66374cf47c9b471ec15da7f322b7ee17ab8`.
The reference includes the previous register experiment and GPU optimizations,
not merely committed HEAD. Its provenance is also recorded in
`.build-tmp/n64-megaman-later-2026-09-23/`.

## The black screen

The CPU and audio task scheduler continued, but graphics stopped after two RSP
tasks and 54 RDP commands, with no triangles, rectangles or fills. RDRAM video
buffers were actually black. The same failure occurred with software rendering
and with the optional register experiment disabled.

`completion-order-before.txt` records both initial graphics jobs. FULL_SYNC
raised DP immediately inside the synchronous RSP interpreter, while RSP BREAK
was hidden for another 1,000 device cycles. The game's DP handler marked jobs
1 and 2 ready; their later SP handlers overwrote that state with 7, meaning
RSP-finished but still awaiting DP. No further DP event could finish them.

Executed FULL_SYNC now schedules a DP event during synchronous RSP dispatch.
It uses the existing 4,000-cycle completion model, while SP retains its existing
1,000-cycle graphics delay. Submission without FULL_SYNC still cannot signal
DP. Direct CPU submissions retain their existing behavior. GPU synchronization
still completes before the emulated interrupt.

The DP timer starts when FULL_SYNC executes, not when an entire RSP task ends.
Thus a task can submit a completed list and then wait for the CPU without
blocking its DP signal. RSP completion no longer restarts an already pending
DP timer. Existing serialized pending-event fields are reused.

The local Mupen64Plus reference at commit
`53a08fceb71653000dd6640cac05eb390fba7885`,
`src/device/rcp/rsp/rsp_core.c:327`, uses the same 1,000/4,000 completion-delay
model. These delays are a scheduling approximation, not cycle-accurate RDP
execution times.

## The second stall: controller initialization

Fixing DP allowed thousands of graphics tasks to run, but exposed a blinking
"No Controller" message. The controller was present in the emulator; the game
had not reached its first SI controller query. Its controller thread was still
waiting inside `osContInit` for the initial timer.

IPL reported PAL correctly, but Memory always scheduled 60 VI fields/s. The
PAL scheduler repeatedly rearmed a frame timer before that timer could expire,
starving the controller initialization timer behind it. The thread and timer
queues are preserved in `boot-dp/rdram.bin`.

Memory now derives one TV type from the cartridge's existing country mapping,
shared with IPL startup:

- PAL: 50 fields/s and a 49,656,530 Hz AI DAC clock.
- NTSC: 60 fields/s and the existing 48,681,812 Hz DAC clock.
- MPAL: 60 fields/s and a 48,628,316 Hz DAC clock.

VI keeps precomputed line-period tables. AI duration uses the corresponding
refresh rate when converting VI timing back into CPU cycles, avoiding a 60/50
stretch of PAL audio. Region is derived from the loaded ROM; no savestate
format or game-specific identifier is added. Clock/rate values were checked
against the same local reference's `src/device/rcp/vi/vi_controller.c`.

## Idle CPU work

The existing bounded idle-loop accelerator also recognizes nontrapping
`ADDIU/DADDIU rx,rx,imm` delay slots. RE2's idle thread increments a counter in
the delay slot of a self branch. The complete counter result is computed,
including 32-bit sign extension or 64-bit wrapping. All existing live-code,
TLB, interrupt, COUNT, watchdog and device-deadline guards remain.

This optimization alone did not fix startup: `boot-counter/` remained black
after hundreds of emulated seconds. The two scheduling fixes above are required.

## Validation and delivery

- The new short-task SP/DP ordering test fails against the frozen old core and
  passes with the fix. It also covers save/restore, no FULL_SYNC, no duplicate
  interrupt, and FULL_SYNC followed by an RSP producer wait.
- 32 RSP slice-boundary cases, framebuffer publication and 197 RDP streaming
  cases pass. The live GPU journal test now advances the device clock before
  checking deferred DP, and verifies there was no premature interrupt.
- 96 regional VI timing cases cover field deadlines, repeated acknowledgement
  and save/restore across 12 country codes and four vertical timings. Existing
  81 framebuffer checks pass.
- Audio FIFO/resampling checks and six regional DAC/DMA deadline cases pass.
  Controller port checks pass.
- 847 idle-loop cases, including 480 accelerated cases and six complete
  two-million-instruction event-serviced replays, pass exact state comparison.
- Rampage, Duke, Mario, Gauntlet and Perfect Dark each replay 50 million
  instructions with identical complete CPU/device/RAM state between ordinary
  interpretation and optimized execution under the new timing model.
- All 58 live GPU checks and six GPU savestate checks pass with Vulkan
  validation and ownership audits; zero validation errors.
- RE2 boots to language selection and the title menu. Its real GPU save/load
  test compares uninterrupted and restored five-second continuations: complete
  CPU/device/RAM/hidden/TMEM state, audio, input and frames are exact.
- Mega Man's new save runs for 30 emulated seconds: all six sampled images,
  audio and task counts match the old timing model. Interrupt timing changes
  input-read timestamps by 28–36 CPU cycles, so full RAM/CPU hashes are not
  asserted against the old model.
- Mario completes two 90-second walking/swimming runs. Default registers and
  the opt-in register experiment agree at all 18 checkpoints, all 18 images and
  final RAM. Relative to the previous interrupt model, 12/18 images match;
  later movement/audio timing shifts slightly. The old oracle is deliberately
  retained, not relabeled as an exact match.
- Normal Release desktop and live GPU desktop builds pass. Their assembly
  hashes are in `delivery-builds.json`. The native GPU library is unchanged.

Functional checks overlapped other functional checks/builds; their wall times
are not performance measurements. The isolated Mega Man measurements are
documented separately in [the later-save report](n64-megaman-later-speed-2026-09-23.md).

Restart the desktop with `./scripts/run-n64-gpu-desktop.sh`, reopen the RE2 ROM
and start from reset. An old state already stuck in the broken graphics job
sequence cannot reconstruct the completion that was previously lost.

The automatic Start/A sequence selected **Load Game** and displayed **Access
error** on this test run. Cartridge save loading is not claimed as fixed here;
the emulator's own GPU savestate continuation is separately verified above.
ROMs and the user's savestate slots were not modified.
