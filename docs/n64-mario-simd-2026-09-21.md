# Mario RSP SIMD, 2026-09-21

Baseline: `48b51bff`. The final combined Linux Super Mario 64 (USA) comparison
improves by **12.19%**, from 59.45% to **66.70% of real time**. Earlier isolated
series measured 16–20% for SIMD and another 3–6% for short vector transfers;
throughput varies between series. Full real-time play remains unfinished.

## Implementation

The MIPS library now builds for both `netstandard2.0` and `net8.0`. The desktop
core already targets .NET 8 and selects the latter. The standard target keeps
the portable interpreter. No new package dependency is needed.

On hosts with SSSE3, 23 RSP vector operations process all eight 16-bit lanes
using native SIMD: multiply, multiply/accumulate, add/subtract with flags,
merge and bitwise logic. Register-byte shuffles combine big-endian conversion
and element selection. Both operands are loaded before any destination write,
including register aliases. The three accumulator planes retain their exact
48-bit wrapping, signed/unsigned saturation and carry behavior.

Both the interpreter and compiled RSP blocks use the same SIMD implementation.
Unsupported operations and hosts use the existing scalar path. The diagnostic
override `EUTHERDRIVE_N64_RSP_SIMD=0` also selects it. Shuffle-table initialization
does not depend on partial-class field initialization order.

Instruction counts, scheduling, emulated clocks, renderer quality, frame
publication and save formats are unchanged. Temporary scalar operand buffers
need not be updated by SIMD. The block-check harness therefore excludes those
five work buffers when comparing executors, while retaining all registers,
accumulators, flags, history, watchdog and device state. Existing task-capture
serialization retains its previous default.

Contiguous 1/2/4/8-byte vector transfers also use unaligned native-word copies.
The fast path proves that neither the 4 KiB DMEM boundary nor the 16-byte
register boundary is crossed. Partial/wrapping transfers, tracing and task
descriptor writes keep their byte implementation. No alignment requirement or
byte-order change is introduced.

## Measurements

Artifacts: `.build-tmp/sm64-simd-2026-09-21/`. `reference/` contains the previous
commit's probe and core; `final/` contains the measured SIMD build. ROM:
`.build-tmp/sm64-speed-2026-09-20/native-game/input.z64`. Gameplay state:
`.build-tmp/sm64-20260919/mario-input/state.bin`.

Each process runs for 40 seconds, pinned to CPUs 6 and 7, discarding the first
ten seconds. Builds and other test processes do not overlap timed runs.
User-owned background applications remain running.

| Serial process order | Reference mean | SIMD mean | Throughput gain |
| --- | ---: | ---: | ---: |
| Reference / SIMD / SIMD / reference | 0.57816 | 0.69283 | 19.83% |
| SIMD / reference / reference / SIMD | 0.60032 | 0.69643 | 16.01% |

These are emulated seconds per wall second, calculated from the cycle-counter
delta divided by the unchanged 93,750,000 cycles/second. The graphics-task
counter includes yielded RSP work and is not display FPS. Results and individual
logs are in `scene-results-*.json` and the matching `scene-*.log` files.

The SIMD-only native sample has 29,933 instruction-pointer samples. Vector
compute/accumulation previously accounted for 10.3% + 4.6% of leaf samples;
SIMD now accounts for 4.1% and remaining scalar vector compute for 3.6%.
Textured triangles (14.4%), CPU block dispatch (10.6%), texture filtering
(5.5% wrap + 2.9% clamp), RSP dispatch and bookkeeping remain significant.
Leaf percentages shift when other work becomes faster; the scene comparisons
above establish the speedup.

The additional transfer change is compared independently against SIMD alone:

| Serial process order | SIMD only | SIMD + transfers | Further gain |
| --- | ---: | ---: | ---: |
| SIMD / transfers / transfers / SIMD | 0.68077 | 0.71997 | 5.76% |
| Transfers / SIMD / SIMD / transfers | 0.68451 | 0.70825 | 3.47% |

Those builds remain under `final/` (SIMD alone) and `transfer/` (both changes)
so all intermediate comparisons are reproducible. The second series shows
background variation; use the paired averages, not the fastest single run.

Final combined check, transfers / reference / reference / transfers:

| Build | Emulated seconds per wall second |
| --- | ---: |
| Both changes, run 1 | 0.66427 |
| Reference, run 2 | 0.59470 |
| Reference, run 3 | 0.59434 |
| Both changes, run 4 | 0.66976 |

Mean **0.59452 to 0.66701, +12.19%**. Use this direct comparison as the
whole-change estimate; isolated gains come from different process series and
should not be compounded. Logs: `scene-transfer-reference-reference-transfer-*`.

## Validation

The differential SIMD check covers **214,696 instructions**, including all
element selectors, register aliases, multiplication extrema, accumulator
overflow/carry, every carry/selection mask and mixed SIMD/scalar sequences.
The 18,560 instruction/transfer cases, 2,048 register-copy cases and 32,768
shuffle cases also pass. Both
strict and legacy half-vector shuffles match the reference. Explicitly disabling
SIMD and disabling SSSE3 through the runtime both pass using the scalar fallback.
Disabling the RSP block JIT also passes with SIMD in the ordinary interpreter.

RSP block tests pass 96 programs, including code replacement, branch delays,
budget boundaries and DMA. Slice scheduling passes 32 boundaries plus save/
restore, CPU/RSP producer-consumer, DP synchronization and framebuffer publication.
Audio FIFO/snapshot/state checks and 24 resampling combinations pass, as do
6,847 render/interrupt cases, 1,092 intensity/alpha cases, 960 rectangle-depth
cases, 24 blender cases and 81 video checks.

The complete serialized CPU, RAM, RSP and device state matches the previous
build after 50 million guest instructions in Mario, Duke, Rampage and Gauntlet,
and 50,000,001 in Perfect Dark. Both SIMD alone and the final combined build
match; hashes are in `replay-results.json` and `transfer-replay-results.json`. Mario remains
`60E842A0596E319755B512E43BD696A42D5270ACC53CC02AFCCE24AE9E6C2BFE`.
These are correctness runs; their instrumented timings are not performance data.

The SIMD-only longer Mario run lasts 91.26 wall seconds, with 47.759 seconds of captured
audio, 77 distinct position samples and continuously advancing graphics/audio
tasks. Reloading its new savestate advances another 20.31 seconds, with 17
positions and 6.669 seconds of audio including a new cold JIT start. Frames at
45/90 seconds and after reload show Mario swimming through the moat. These
changing scenes are functional/playability checks, separate from the paired
comparison scene. Controls are scheduled in wall time, so faster execution also
changes the exact path through the scene.

The final combined build also completes this play/reload check: **91.29 wall
seconds, 45.341 seconds of audio (49.7% of real time), 77 distinct positions**.
Graphics tasks advance from 1,940 to 5,078 and audio tasks from 4,113 to 6,812,
with no unknown CPU opcodes. Its new save reloads for 20.37 wall seconds,
producing 6.757 seconds of audio and 17 positions. This is the practical limit
observed in the more demanding moving scene, not full-speed play. Evidence:
`transfer-play-results.json`, `mario-transfer-play/`, `mario-transfer-reload/`.

Linux UI Release builds with zero errors and 383 existing warnings. Probe and
UI `Ryu64.MIPS.dll` SHA-256 both equal
`4bc10717f5b151df0fd3a638298533a658fec5fc641378da4fd90ab7f6c8a59b`.
User savestate slots are untouched;
all test saves and captures stay under the artifact directory. Restart the UI
to load the new library.

## Continuation

The final combined sample (`transfer-native/`, 29,946 samples) still puts
textured triangle rasterization at 14.3%, wrap/clamp texture filtering at
5.3% + 3.1%, CPU block dispatch at 10.1%, RSP slice dispatch at 5.3% and
SIMD math at 4.4%. These are the next measured targets. Keep the software
renderer's alpha/depth and frame-publication behavior covered by exact-state
and rendering checks when changing its hot loops.
