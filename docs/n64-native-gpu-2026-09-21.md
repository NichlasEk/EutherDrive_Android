# N64 native GPU boundary checkpoint — 2026-09-21

The C# renderer replay now calls a separate `libeuther_n64_gpu.so.1` through a
small C ABI. Deferring provably unrelated CPU writes removes most forced GPU
waits in the ordered Mario startup journal while preserving every reference
memory byte. This finishes a useful headless integration milestone, not live
GPU rendering. The emulator's software path remains the default.

## Measured result

RTX 4090, Xeon E5-2697 v3, Linux, cores 6/7, normal .NET 8 runtime. The existing
20-checkpoint **startup-logo** recording contains 15,090 complete commands and
31,852 external write ranges totaling 3,347,529 bytes. It is not a gameplay
recording. At each checkpoint all 8 MiB RDRAM, 4 MiB hidden memory and 4 KiB
TMEM match an independent Angrylion export exactly.

| Mode | Host-write barriers over 20 checkpoints | Warm replay median |
| --- | ---: | ---: |
| Strict ordering with a wait before each write group | 15,089 | 158.90 ms |
| Batching only across state commands | 13,673 | Not benchmarked |
| Batching across provably disjoint draws | 106 | 5.98 ms |

Barrier count falls 99.30%. Across three interleaved runs per measured mode,
strict medians were 159.25 / 123.48 / 158.90 ms; range medians were
6.08 / 5.98 / 5.74 ms. The median-of-run-medians reduction is **96.24%** against
the deliberately conservative first GPU bridge. It is not a 96% improvement
over the current software emulator and cannot be converted to a real-time
percentage for Mario.

The wall timer includes submission/marshaling, input copy and byte conversion,
GPU rendering/waits, complete memory readback/byte conversion and frame-context
advance. It excludes reference parsing, hashes, disk I/O and initialization.
The latter took 308–350 ms. All-20-frame totals including cold shader work were
3.94–4.18 s strict and 1.63–1.78 s batched. Cold compilation remains material.
Warm medians exclude the first five checkpoints of each run. Two validated
full replays precede six interleaved measured replays. Hash comparisons remain
enabled in every run; only Vulkan validation is disabled during timing.

## What changed

- `native/N64Gpu`: ABI 1, isolated context lifetime, aligned memory import,
  exact patch staging, timeline wait/readback, statistics, versioned exports,
  argument/error boundaries, native tests and an interleaved timing driver.
- `Ryu64Core.N64GpuBackend`: explicit dynamic loading and SafeHandle lifetime
  leases, including calls/disposal from different managed threads.
- `N64Probe`: ordered journal replay across that boundary, lifecycle checks
  and a ten-checkpoint synthetic memory-hazard recording.
- `N64GpuProbe --journal-reference`: export independent native memory at every
  FULL_SYNC. Its Angrylion code stays out of the production shared library.

The batcher never removes write records or estimates which byte values matter.
It defers their application until the next dependency. Draw bounds include
the whole possible 1024-row pass of both color and depth buffers, aligned byte
accesses for every color size, and the backend's RAM address wrapping. A simple
bounding interval for all pending patches may wait unnecessarily but cannot
declare a contained patch independent. State changes update the tracked
targets. Texture loads, unknown commands, missing state, FULL_SYNC and public
submission boundaries keep conservative waits. GPU work completes before the
exact deferred patches are applied, preserving earlier GPU results.

The proof depends on the pinned unscaled renderer: `op_set_color_image`,
`op_set_mask_image`, `update_deduced_height`, and `init_tile`/`finish_tile` in
`parallel-rdp/shaders/memory_interfacing.h`. Build instructions and ABI details
are in [native/N64Gpu/README.md](../native/N64Gpu/README.md).

## Verification

- Mario: all 20 full-memory checkpoints exact with strict, state-only and
  range batching. Khronos synchronization validation: zero errors on valid
  replays. The six timed runs also check all memory hashes.
- Existing two-checkpoint fixture: exact unaligned/same-value CPU writes,
  neighboring GPU pixels, DMA/mirrored writes and changed texture inputs.
- New ten-checkpoint fixture: exact color overwrite ordering, target/width
  changes, maximum scissor Y, four pixel sizes, primitive depth compare/update,
  conservative wrapped target ranges and texture reloads. Strict uses 25 write
  barriers; range batching uses 18.
- Native ABI: 68 successful assertions/API checks in the recorded run cover
  malformed/partial/overflowing buffers, atomic argument rejection, timelines,
  all byte lanes, isolated contexts, cross-thread destruction, stale handles,
  disjoint/overlapping/wrapped ranges and a hardware-invalid RDP command that
  must report failure. The error may be observed at submit or completion.
- Managed adapter: 13 checks cover buffer/error propagation, concurrent
  calls/disposal, double disposal, disposed-handle calls, finalization and
  recreation after unloading.
- A deliberately corrupted oracle byte is rejected at frame 1. Warm hardware
  state import is rejected rather than guessed.
- Normal Release build passes. Production `Memory` retains all 382 fields,
  453 methods and 108,179 IL bytes from the accepted pre-journal build, with
  zero capture-observer members. The managed ABI lifecycle check also passes
  in this normal build.
- The shared library exports only eight `ed_n64_gpu_*` functions and its
  version node. The Ninja dependency graph contains no Angrylion, `alp-core`
  or `rdp-utils`. Those remain separate development-only oracle dependencies.

## Limits found and remaining work

A deliberately out-of-installed-RAM framebuffer draw differs between the
pinned backends even with strict barriers: paraLLEl masks shader addresses to
the installed RAM size, while Angrylion bounds-checks the installed memory
after its wider address mask. This is an unresolved backend accuracy case,
not an accepted exact replay. Its failing original journal/log are retained
locally. Passing hazard tests keep actual rendering inside installed memory
while exercising wrapped *conservative* dependency ranges.

ABI 1 currently requires coherent external host-memory import and the tested
small-integer NVIDIA shader configuration. The fallback memory path, default
NVIDIA shader path, other GPUs, relocatable shader assets, device-loss recovery,
timeouts and hardware savestate import are not validated for production.

The next stage is live memory ownership. First record/audit CPU and DMA reads
of pending render targets, including JIT fast paths and RSP DMA. Then an opt-in
live backend can synchronize those dependencies and FULL_SYNC before exposing
authoritative GPU output or raising the existing DP interrupt. It must preserve
CPU/RSP execution, DPC FIFO/current behavior, texture input order, JIT cache
invalidation, save/load and frame visibility. Full-memory replay readback is
deliberately conservative; partial readback requires its own ownership proof.

Measure simulated time/wall time and new completed game frames only after that
stage works. Existing savestates and the user's running app were not modified.
See stages 3–6 of the [integration plan](n64-gpu-backend-plan-2026-09-21.md).
